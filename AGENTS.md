# Profile repository guidance

## Repository role

This repository publishes Cheng's GitHub profile. Its `README.md` is generated by the sibling `chengchuu.github.io` repository; this repository does not own project metadata or an npm build.

## Maintained files

- Preserve the user-authored introduction and its selected image. Keep existing image assets unless their removal is requested.
- Maintain issue templates under `.github/ISSUE_TEMPLATE/` directly.
- Maintain `.github/workflows/update-profile.yml` here. It checks out the sibling generator, refreshes metadata, generates `README.md`, and commits the README only when its content changes.
- Keep system files, dependencies, build output, and temporary files ignored.

## Generated README

Do not hand-edit project rows, dates, categories, or resource links in `README.md`. Make those changes in:

```text
../chengchuu.github.io/src/config/projects.ts
```

Generate the README from the sibling repository:

```bash
cd /Users/cheng/web/chengchuu/chengchuu.github.io
npm run generate:data
npm run generate:readme -- --output ../chengchuu/README.md
```

Metadata generation uses GitHub, npm, and the Go module proxy. Preserve existing valid metadata and report degraded results when a source is unavailable.

Contributions appear in a Project/Links/Description table before npm, with plain-text project names and linked `owner/repository` identifiers in Links, without upstream dates or versions. They follow the same README visibility setting as other projects.

The generated tables for other categories must:

- Use only `Project`, `Links`, `Created`, and `Latest release` columns.
- Keep npm and Go projects in their correct sections.
- Include every canonical project unless `hideFromProfileReadme` is `true` in the sibling `src/config/projects.ts`. Omit unavailable resource links and empty categories.
- Exclude status, relationship, owner, and maintainer fields.

## Verification

After a README or workflow change, run:

```bash
git diff --check
git status --short
```

Inspect the generated-file comment, preserved introduction and image, table headers when projects are visible, and coverage of all README-visible projects. For generator behavior or metadata changes, use `npm run check` in `../chengchuu.github.io` instead of adding scripts or dependencies here.

## Profile README ownership

The content above the generated-file comment in the profile README is user-authored. Edit the introduction and image there directly; generation preserves that prefix exactly. The comment marks the beginning of the generated project section, which extends to the end of the file. Keep exactly one marker. Generation refuses to overwrite an existing README with a missing or duplicate marker.

A new output file contains only the generated marker and project sections. Add personal content above the marker. Existing project rows remain generated from the canonical project configuration; do not edit them manually.
